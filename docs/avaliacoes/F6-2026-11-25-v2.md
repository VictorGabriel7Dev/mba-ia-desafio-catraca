## Contexto desta rodada

Esta é uma REAVALIAÇÃO após a correção em que a compra pela API passou a rejeitar e-mail mal formado com `422 invalid_request`, e o contrato C-F6-02 foi reforçado para cobrir esse gatilho (agora o enunciado inclui "e-mail mal formado -> 422"). O foco especial foi reverificar, no C-F6-02, TODOS os gatilhos de `422` (cartão fora de 16 dígitos, e-mail mal formado e campo faltando) e a ordem completa de precedência de erros `401 -> 422 -> 404 -> 409` descrita em `_CONVENCOES.md`. Os demais itens (C-F6-01, C-F6-03, C-F6-04, C-F6-05) foram reexercitados do zero neste commit.

## Método

Cada item do contrato (C-F6-01 a C-F6-05) foi exercitado de forma independente com `curl` contra a API no ar. Os dados foram criados como a organizadora da seed (`ana.organizadora@catraca.dev`) com nomes de evento de sufixo único (`F6v2-...-1795641291`) para não colidir com avaliadores paralelos. Foram criados eventos próprios: um rascunho (DRAFT, lotação 10), um publicado com lotação 3 (PUB), um publicado com lotação 1 (CHEIO, para `sold_out`), um publicado e depois cancelado (CANCEL) e um publicado para o teste de cancelamento/estorno (ESTORNO, lotação 4). A chave de parceiro usada foi `X-Api-Key: parceiro-demo-key-123`.
