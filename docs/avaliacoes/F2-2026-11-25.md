# Avaliação independente F2: Eventos (ciclo de vida)

- **Feature:** F2 (Eventos / ciclo de vida)
- **Data:** 2026-11-25
- **Commit avaliado:** e05e9e1
- **Ferramenta:** curl contra o stack vivo em `http://localhost:4000` + leitura de código em `api/src/`
- **Avaliador:** agente de avaliação independente Claude (Opus 4.8), contexto separado do implementador (não escreveu este código)

## Método

Cada item do contrato C-F2-01..08 foi exercitado de forma independente com `curl` contra a API no ar. Para não colidir com avaliadores paralelos, os eventos foram criados com nome de sufixo único (ex.: `F2EV-1795637217-19520 ok`). As compras usaram a participante da seed (`carla.participante@catraca.dev`) com cartão de 16 dígitos de final `0001`. A leitura de código (`domain/evento.ts`, `services/event-service.ts`, `repositories/ticket-repository.ts`, `http/organizer-routes.ts`) serviu apenas para fundamentar o comportamento observado. As credenciais de organizador foram `ana.organizadora@catraca.dev` (dona dos eventos) e `bruno.organizador@catraca.dev` (segundo organizador, para o isolamento).

## Veredito final

**APROVADO.** Todos os oito itens do contrato (C-F2-01 a C-F2-08) passaram, verificados de forma independente contra o stack vivo no commit e05e9e1 e corroborados por leitura de código. Não houve item reprovado.

## Observação (não bloqueante)

A validação distingue corretamente inteiro de fracionário em `capacity` (via `Number.isInteger`) e exige `priceCents` estritamente maior que zero. O isolamento entre organizadores usa a ordem correta de erros (404 para evento inexistente, 403 para evento de outro dono), o que evita vazar a existência de ids de terceiros apenas quando o id de fato não existe.
